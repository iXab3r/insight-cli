# Independent string-anchor API review

Verdict: **APPROVE_WITH_NONBLOCKING_NOTES**

Scope: review of the proposed public V1 contract, the independent two-sided probe/preview/page-reader clarification, and matched before/after method. No implementation, native execution, prior investigation findings, or benchmark results were used. The existing design, coordinator guidance, and current research/query/cursor source were read for architectural fit. Existing unrelated working-tree changes were left untouched.

## Assessment

The proposed command is useful for sparse analysis: an exact raw encoded-byte hit remains useful when defined string data, function containment, and stored references are absent. Retaining both `matchAddress` and a separately qualified `literalCandidate` avoids conflating an interior reference with a literal's beginning. Limiting V1 to a literal, explicit encodings, initialized byte-addressed default-space memory, and an inclusive explicit range makes the search domain explainable and testable.

The precompiled authenticated ReadOnly endpoint fits the existing facade/bridge model. Before/after native observations within the same ordered context action, plus native modification checks, are appropriate. No Factory change, analysis, definitions, save, automatic joins, cache, or query-state registry is needed. Existing indexed-string and byte-pattern contracts can remain intact.

I found no inherent contradiction requiring redesign or owner clarification. The numerical limits are workable: the largest UTF-16LE needle is 512 bytes; the 8192-byte total payload cap permits bounded context recovery; and a 32768-byte minimum page budget can accommodate one deliberately bounded atomic candidate operation. A single maximum-sized row, including worst-case JSON escaping, fits comfortably below the proposed one-MiB output cap. These facts do not replace an implementation proof of actual read accounting and progress.

## Nonblocking specification and implementation notes

1. **Document the clarified two-sided recovery rule.** Independent NUL probes up to `cap - needleBytes` on each side can find every complete candidate whose total payload fits the cap, regardless of the needle's position. Finding both boundaries does not permit returning an oversized payload. For incomplete/oversized candidates, the clarified balanced preview allocation, rounded to encoding units with deterministic spare transfer, is acceptable. Version this rule with the algorithm. Keep nullable candidate start/terminator separate from `textFrom`, `text`, and `textByteLength`; a preview address must not masquerade as the full literal's start. Distinguish NUL, clipped-span edge, and context-cap evidence. The example's 26-byte offset and 46-byte payload are internally consistent.

2. **Bind UTF-16 code-unit phase to each byte hit.** Every byte may be a match start, including odd addresses. Search for NUL *code units* by stepping two bytes relative to that hit, not by searching arbitrary overlapping `00 00` pairs or enforcing image alignment. Do not bridge a hole or read a code unit partially outside the clipped span. Decode context strictly; lone surrogates or non-ASCII surrounding bytes can invalidate context without invalidating the exact raw hit. Keep byte-boundary completeness and successful decoding separate. NUL terminators are not payload, and the query itself cannot contain one.

3. **Keep raw pairs, including duplicates and overlaps.** Canonical result order should be numeric address, then the stated ASCII/UTF-16LE encoding order. Two hits in one candidate literal remain separate. The same address in both encodings remains two pairs. Overlapping occurrences advance by one byte. In particular, a one-character ASCII query can match the low byte of a UTF-16 string; this follows the declared raw-search semantics and should not be filtered by a text heuristic.

4. **Treat emission and the frontier atomically.** A pair is checked only once its miss is established, or its hit/context result is finalized and included in the response. When scan prefetch has consumed the room needed for context, stop with the matched pair still at the frontier. Likewise, output-cap/result-limit checks must occur before advancing past an unreturned row. Do not emit a budget-dependent context failure merely because this page ran out of read budget: resume the same pair instead. Encoding must be in the cursor so stopping after ASCII at address A does not skip UTF-16LE at A. Context recovery must remain bounded even when no NUL exists.

5. **Prove the minimum-budget progress invariant in code.** The clarified 4096-byte, eight-page bounded LRU reader is a reasonable way to keep one fresh candidate below 32768 bytes, including page-boundary overhead. Align pages to absolute addresses and clip reads to the allowed initialized span; do not fetch outside the public range just to fill a cache page. Actual metering still needs to cover resumed-candidate reads, lookahead, terminator probes, and rereads after eviction. Do not force a full scan chunk read before an atomic candidate if that spends its needed allowance. With unchanged memory and a positive effective deadline, a continuation at a hit must be able to consume that pair using the minimum accepted byte budget. Cooperative timeouts may legitimately return no progress, but should not be hidden as successful exhaustion.

6. **Be precise about counters and completion.** Count matched `(address, encoding)` pairs toward `max-candidates`, including invalid or incomplete context, rather than unique reconstructed literals. Count actual scan/context/lookahead/reread bytes consistently. Counters should be page-local; any cumulative coverage is derived from retained page results. Exhausting the eligible search domain is distinct from every returned candidate having complete boundaries or valid decoding. Keep timeout, byte limit, candidate limit, result limit, and exhausted explicit. At the final eligible pair, prefer exhausted if no unchecked pair remains. Empty ranges of eligible memory are complete searches of an empty domain.

7. **Retain strict cursor validation.** Revalidate every untrusted field and cross-field constraint, including encoding membership, unsigned address range, the frontier's encoding slot, context cap, and algorithm version. Scope and immutable selectors cannot be overridden with a continuation. Page byte/candidate/result/deadline budgets can change and omitted controls can inherit the prior page. Recompute the complete current view and reject changed views before returning rows. An edited token can choose a later valid frontier; that is acceptable only because the token expressly provides no proof of earlier coverage. Avoid describing an unsigned token as authenticated.

8. **Check the actual serialized envelope.** Reserve space for metadata and cursor, not just the rows, when enforcing one MiB. Ensure maximum escaping still allows at least one row. If even an individual valid row cannot fit, return a clear error rather than a permanently nonadvancing `result_limit` cursor. The current bounds make this avoidable.

## Matched before/after methodology

The proposed baseline—raw encoded-byte search followed by bounded context memory reads—is the correct workflow comparator. Indexed strings are not an equivalent baseline. Use a disposable sparse fixture and the same persistent frontend for both paths. Verify ordered raw hit pairs and every context/boundary/decoding field independently before interpreting timing.

The existing byte-pattern implementation reads initialized blocks separately and does not have the new command's exact inclusive-end/adjacent-span contract. Therefore do not assume all fixtures are automatically equivalent. For the timed comparison, use a clearly declared eligible domain where the old workflow can reproduce the same results, or adapt the baseline workflow explicitly and include that work in its timing. Test adjacent-block matches, clipped boundaries, holes, odd-address UTF-16, overlaps, multiple encodings, invalid context, and budget continuations as correctness cases regardless of whether the old command can natively express them.

Report full workflow wall time and native operation time separately, with exact timed boundaries, call counts, bytes, page counts, warm-up policy, repeated trials, and result equivalence. Keep process startup/opening outside both or inside both. Persistent frontend use removes repeated frontend startup but does not make native transports equivalent. The old helper's compilation/dispatch overhead versus a precompiled endpoint is a real end-to-end difference; describe the measured improvement as the combined workflow/transport change, not proof that fusion alone caused it. Do not claim a cold-start benefit from warm persistent measurements, or broader application performance from one disposable corpus.

## Focused acceptance evidence

The implementation should demonstrate: exact interior-address preservation; UTF-16 at both address parities; repeated and overlapping hits; a hit across adjacent initialized blocks; no match across a hole; no out-of-range match/context/terminator read; both-sided and one-sided missing boundaries; cap exhaustion and invalid context without loss of raw hits; continuation between two encodings at one address; minimum-byte-budget progress; stop-before-unreturned-row behavior; unchanged-view continuation; and changed-view rejection before/after the operation. Default tests remain offline, with native writes confined to explicitly created disposable fixtures.
